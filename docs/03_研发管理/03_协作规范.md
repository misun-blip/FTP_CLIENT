# 协作规范

## 1. 协作目标

项目协作需要同时满足三点：

1. 多人能够并行开发
2. 公共接口保持稳定
3. 主分支始终保留可运行版本

本项目采用：

- 模块负责人制
- 接口先行
- 分支开发
- 小步提交
- 定期联调
- 代码评审后合并

## 2. 代码归属

| 目录或文件 | 主负责人 |
|---|---|
| `core/` | 成员 2 |
| `transfer/downloader.py` | 成员 3 |
| `transfer/download_resume.py` | 成员 3 |
| `transfer/uploader.py` | 成员 4 |
| `transfer/upload_resume.py` | 成员 4 |
| `ui/` | 成员 5 |
| `utils/`、`tests/` | 成员 6 |
| `main.py`、`models/`、集成装配 | 成员 1 |

规则：

1. 主负责人对本模块最终质量负责
2. 其他成员如需修改该模块，应先与主负责人沟通
3. 公共文件不得多人长期并行修改
4. 公共接口变更必须同步更新接口文档

## 3. 分支管理

### 3.1 分支类型

```text
main                 # 稳定可运行版本
develop              # 日常集成分支
feature/login        # 功能开发
feature/download
feature/upload
feature/gui
fix/resume-bug       # 缺陷修复
docs/interface       # 文档更新
```

### 3.2 使用规则

1. `main` 只保留可演示版本
2. 日常开发基于 `develop`
3. 每个功能使用独立分支
4. 每个分支只处理一类问题
5. 功能完成后先合并到 `develop`
6. 经过集成测试后，再由项目统筹合并到 `main`

## 4. 提交规范

### 4.1 提交粒度

每次提交尽量只完成一件事，例如：

- 一个接口
- 一个 bug 修复
- 一个测试用例
- 一份文档更新

### 4.2 提交信息

```text
feat: add passive mode support
fix: handle interrupted download
ui: add transfer progress view
docs: update interface design
test: add resume test cases
```

## 5. 接口协作规则

### 5.1 接口先行

进入大规模开发前，先确定：

- 函数名
- 参数
- 返回值
- 异常形式
- 调用顺序

### 5.2 接口冻结

核心开发阶段后，以下基础接口进入冻结期：

- `connect()`
- `login()`
- `list_dir()`
- `upload()`
- `download()`
- `resume_upload()`
- `resume_download()`

若必须修改：

1. 先在文档中提出变更
2. 通知受影响成员
3. 修改接口文档
4. 同步更新调用方
5. 重新执行相关测试

## 6. 联调机制

| 阶段 | 联调内容 |
|---|---|
| 第一次联调 | 登录、目录浏览 |
| 第二次联调 | 上传、下载与 GUI |
| 第三次联调 | 断点续传、异常处理、完整流程 |

模块进入联调前，至少应满足：

1. 自测通过
2. 对外接口已实现
3. 已提供最小使用示例
4. 已记录已知限制

## 7. 代码评审

1. 任何合并到 `develop` 的代码，至少由 1 名其他成员查看
2. 涉及公共接口的变更，由受影响模块负责人共同确认
3. 评审重点：
   - 是否符合接口约定
   - 是否引入明显阻塞或异常
   - 是否破坏已有功能
   - 是否同步更新测试和文档

## 8. 冲突预防与处理

### 8.1 预防措施

1. 提前划分目录归属
2. 公共接口先定稿
3. 减少多人同时修改同一文件
4. 小步提交、及时同步最新代码
5. 定期联调，而不是最后一次性合并

### 8.2 冲突处理

若出现代码冲突：

1. 优先依据接口文档判断正确行为
2. 保留主负责人模块内的最终实现权
3. 必要时由项目统筹组织协商
4. 冲突解决后重新运行相关测试

## 9. 缺陷管理

每个缺陷至少记录：

- 发现时间
- 触发条件
- 现象
- 责任模块
- 严重程度
- 当前状态

状态建议：

- `open`
- `in_progress`
- `fixed`
- `verified`
- `closed`

## 10. 推荐协作节奏

```text
接口先定
  ↓
模块并行开发
  ↓
每周至少一次集成
  ↓
测试同步跟进
  ↓
问题即时修复
  ↓
稳定版本进入 main
```
