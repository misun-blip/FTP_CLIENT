# 成员 2 接入指南

## 1. 目标

成员 2 负责将真实 FTP 协议层接入应用骨架，使系统能够从 mock 模式切换到真实连接模式。

## 2. 需要实现的接口

协议层至少需要实现以下方法：

```python
connect(host: str, port: int, timeout: int = 10) -> None
login(username: str, password: str) -> bool
list_dir(path: str | None = None) -> list[RemoteFile]
close() -> None
```

这些方法需要满足 `FTPClientProtocol` 约定。

## 3. 推荐文件位置

```text
ftp_client/core/
├─ connection.py
├─ response_parser.py
└─ ftp_client.py
```

## 4. 推荐类结构

```python
class FTPClient:
    def connect(self, host: str, port: int, timeout: int = 10) -> None:
        ...

    def login(self, username: str, password: str) -> bool:
        ...

    def list_dir(self, path: str | None = None) -> list[RemoteFile]:
        ...

    def close(self) -> None:
        ...
```

## 5. 接入步骤

### 第一步：完成协议层最小实现

先只完成：

1. 建立控制连接
2. 登录
3. 获取目录列表

不要一开始同时处理上传、下载和全部异常。

### 第二步：保证返回统一模型

`list_dir()` 必须返回：

```python
list[RemoteFile]
```

不建议把原始字符串直接抛给上层，否则 GUI 和其他模块会反复做解析。

### 第三步：在装配层接入真实对象

后续由成员 1 在 `create_app()` 中把真实 `FTPClient` 注入：

```python
services.ftp_client = FTPClient()
```

### 第四步：运行首次联调

验证：

1. 应用层能拿到真实 `ftp_client`
2. `connect()` 可用
3. `login()` 可用
4. `list_dir()` 能返回标准 `RemoteFile`

## 6. 联调前自检

- [ ] 不依赖 `ftplib`
- [ ] 可建立 TCP 控制连接
- [ ] 能正确处理欢迎响应
- [ ] 能发送 `USER` / `PASS`
- [ ] 能解析至少基础响应码
- [ ] `list_dir()` 返回统一模型
- [ ] 遇到异常时不会让程序无提示退出

## 7. 常见错误

| 问题 | 后果 |
|---|---|
| `list_dir()` 返回原始字符串 | GUI 和业务层无法直接复用 |
| 连接和登录写成一个巨型函数 | 后续测试困难 |
| 响应解析和 socket 操作完全混在一起 | 维护成本高 |
| 在协议层直接处理 GUI 行为 | 层次混乱 |

## 8. 完成标准

成员 2 的第一阶段完成标准不是“FTP 所有功能都写完”，而是：

1. 协议层对象可被应用层注入
2. 能成功登录测试服务器
3. 能返回统一格式的远程目录列表
4. 能通过首次联调
