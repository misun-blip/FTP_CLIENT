# 测试方案

## 1. 测试目标

验证系统在正常场景和异常场景下均能满足功能要求，并保证演示过程稳定。

## 2. 测试环境

| 项目       | 说明                   |
| ---------- | ---------------------- |
| 操作系统   | Windows                |
| 开发语言   | Python                 |
| GUI 框架   | PySide6                |
| FTP 服务器 | 本地或局域网测试服务器 |
| 网络方式   | TCP                    |

## 3. 测试类型

1. 功能测试
2. 接口测试
3. 异常测试
4. 断点续传测试
5. 界面测试
6. 集成测试
7. 公共支撑测试（日志、配置、异常封装）

## 4. 测试时机

测试不应等待全部开发完成后才开始，而应随项目阶段同步推进。

| 阶段           | 测试重点                                     |
| -------------- | -------------------------------------------- |
| 需求与设计阶段 | 明确验收标准，编写测试用例初稿               |
| 基础开发阶段   | 对连接、登录、目录接口进行单元测试与接口测试 |
| 核心开发阶段   | 对上传、下载、续传进行功能测试               |
| 联调阶段       | 进行模块集成测试和界面联调测试               |
| 交付前阶段     | 进行回归测试、异常测试和演示流程验证         |

## 5. 测试分工

| 责任方         | 主要任务                                                     |
| -------------- | ------------------------------------------------------------ |
| 各模块开发人员 | 为自己负责的模块提供最小可复现测试、完成自测                 |
| 测试负责人     | 编写测试方案、维护测试用例、执行接口测试和集成测试、记录缺陷 |
| 项目统筹       | 组织版本验收、确认关键缺陷是否关闭                           |

## 6. 缺陷流转

```text
发现问题
  ↓
记录缺陷
  ↓
分配责任人
  ↓
修复
  ↓
复测
  ↓
关闭 / 重新打开
```

## 7. 成员 6 公共支撑测试范围

| 模块 | 测试重点 |
|---|---|
| 日志模块 | `info`、`error` 可调用，日志可输出到控制台或文件，重复获取 logger 不应重复添加 handler |
| 配置模块 | 缺省配置可加载，JSON 配置可保存和读取，非法端口、超时、日志级别应被拒绝 |
| 异常模块 | 项目异常统一继承，配置、协议、连接、认证、传输异常可区分 |
| 缺陷记录 | 缺陷必须记录状态、责任人、复测结果和关闭条件 |
